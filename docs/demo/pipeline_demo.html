The pipeline

Follow one record through

The 311 complaint above — free text, a vague location, a dead screen, and a made-up "urgent-safety" label — traced through all four stages of the real run.

Stage 1 · Ingestion — Emlyn

LLM/NLP parsing: unstructured text becomes a typed record

Format-detecting readers for CSV, GeoJSON, and free text. The extraction layer reads the contractor's prose and emits a structured maintenance event — values still verbatim, nothing silently altered.

fieldextracted from free text
event_idmaint-2225ba317e29
event_typeCOMPLAINT ← classified from prose
severity"urgent-safety" → SAFETY
location"JON - Jerome 190th Street Municipal Parking" ← pulled from quotes
sessions, same file"08/21/2025" + "19:10:54.0000000" (kept raw — fixing is Stage 2's job)
Stage 2 · Validation & cleaning — Sanja

A declarative rule engine fixes what it can, flags what it can't

Dates to ISO, units repaired, enums normalized, territory checked. Every fix is logged in the record itself; nothing is ever silently dropped.

fieldbefore → after
session start_time"08/21/2025 19:10:54.0000000" → "2025-08-21T19:10:54-04:00" ← correct NY daylight-saving offset
event_date"9/23/24" → "2024-09-23"
energy_kwh"41.369" (string) → 41.369 (number)
fixes_applied["date:start_time:'08/21/2025 19:10:54.0000000'→…"] — every fix logged in the record
issues flaggedstale_report, outside_territory — flagged, never silently dropped
Stage 3 · Reconciliation — Yash

Fuzzy matching across sources builds the single source of truth

Records describing the same physical charger are clustered across all three sources; field conflicts are resolved by explicit survivorship rules; duplicates and billing anomalies are detected statistically.

golden-record evidence (real output)
merged_from4 registry entries for "NISSAN FAST CHR RIVERHEAD" → one charger; 1,697 stale/duplicate registry listings absorbed, every merge reversible via the audit trail
conflicts resolvednetwork: "ChargePoint Network" chosen, "Non-Networked", "Blink Network" rejected — 2,731 conflicts resolved by survivorship rules
golden_idmnt-6ba48a9631bc6f4340f4 ← stable across re-runs
anomalies found2,222 duplicate-billing patterns · 2,100 energy outliers · 82 utilization cliffs · 3 unresolved SAFETY events
Stage 4 · Reporting — Emily

PSC compliance report with a full audit trail

Regulatory KPIs plus a data-lineage appendix — record counts in and out of every stage, per-contractor quality scores, quarantine summary — so “accurate and on time” is demonstrable, not asserted. The broken latch lands on the safety triage list.

Wrapped around all four: the platform layer (Anastasia) — orchestration, retries, health monitoring, and a resumability manifest that detects late-arriving contractor files and re-runs exactly the affected stages. A 298-test contract harness caught and localized every integration bug at merge time — and absorbed the official dataset with only a reader change, exactly as the frozen contract promised.

Built by five people simultaneously on five branches against a frozen data contract — merged with zero file conflicts. And because every golden record carries its full merge history, an adversarial audit could reconstruct every single removal back to its source line — it caught the first reconciliation pass being too aggressive, drove a fix (a duplicate must be the same driver on the same charge box), and verified the corrected run record-by-record. A cleansing framework you can audit is a cleansing framework a regulator can trust. Reproduce from the repo root:

python -m src.platform.run --pipeline full --config src/platform/config.yaml --no-llm
